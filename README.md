# سجل المخزون — برنامج تسجيل صرف الأصناف

برنامج Flask بسيط لتسجيل صرف المشروبات والمهمات (شاي، بن، نسكافيه...) بديل عن ملف الإكسيل،
مع حساب السعر أوتوماتيك، وتقرير شهري بالإجمالي وإمكانية الطباعة.

## الصفحات
- **الأصناف والأسعار** `/items` — تضيف اسم كل صنف وسعر الوحدة بتاعه.
- **تسجيل الصرف** `/entries` — تختار الصنف والكمية والتاريخ، واليوم والسعر بيتحسبوا لوحدهم.
- **التقرير الشهري** `/` — إجمالي السعر للشهر، الإجمالي حسب كل صنف، وتفصيل يومي — وزرار طباعة.

## التشغيل على جهازك (اختياري، للتجربة قبل الرفع)
```bash
pip install -r requirements.txt
python app.py
```
هيفتح على `http://localhost:5000`.

## الرفع على Railway
1. اعمل مشروع جديد على [railway.app](https://railway.app) واختار **Deploy from GitHub repo**
   (ارفع مجلد المشروع ده على GitHub الأول)، أو استخدم **Railway CLI**:
   ```bash
   npm i -g @railway/cli
   railway login
   railway init
   railway up
   ```
2. Railway هيكتشف `Procfile` و `requirements.txt` أوتوماتيك ويعمل build و deploy.
3. **مهم — لحفظ البيانات بشكل دائم**، اعمل واحدة من دول:
   - **الأسهل:** من تبويب Railway، ضيف **PostgreSQL** plugin للمشروع، وهيظهر متغير
     `DATABASE_URL` تلقائي — البرنامج بيقراه لوحده ويستخدمه بدل SQLite.
   - أو ضيف **Volume** واربطه بمسار زي `/data`، وحط متغير بيئة
     `SQLITE_PATH=/data/data.db` عشان قاعدة بيانات SQLite متتمسحش مع كل deploy.
   - لو من غير أي منهم، البيانات هتتخزن في SQLite على القرص المؤقت وممكن تتمسح
     عند أي إعادة تشغيل — مناسب للتجربة بس مش للاستخدام الحقيقي.
4. مفيش حاجة تانية — أول ما السيرفر يشتغل، هو بينشئ الجداول لوحده.

## متغيرات البيئة (اختيارية)
| المتغير | الوصف |
|---|---|
| `SECRET_KEY` | مفتاح سري لجلسات Flask (استخدم قيمة عشوائية في الإنتاج) |
| `DATABASE_URL` | رابط قاعدة بيانات (Postgres مثلاً) — لو موجود بيتم استخدامه بدل SQLite |
| `SQLITE_PATH` | مسار ملف SQLite لو مش مستخدم Postgres (مثلاً `/data/data.db` مع Volume) |
| `PORT` | البورت (Railway بيحطه أوتوماتيك) |

## بنية المشروع
